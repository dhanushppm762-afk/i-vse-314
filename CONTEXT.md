**Два «бэкенда» с одинаковыми маршрутами:**
- **В приложении для Mac** страница грузится с `venice://app/`, запросы `/api/*` обрабатывает
  `Backend.swift` (WKURLSchemeHandler). Python не нужен, порт не открывается.
- **Браузерная версия** — `server.py` на `http://localhost:8765`. Нужна для разработки и проверки
  интерфейса в браузере. Встроенного браузера-агента и смены ключа там нет.

При изменении маршрутов **меняй оба**: `Backend.swift` и `server.py`.

### Маршруты API (оба сервера)
| Маршрут | Что делает |
|---|---|
| `GET /api/config` | модель по умолчанию |
| `GET /api/models?type=text\|image\|inpaint\|upscale` | модели Venice: name, vision, reasoning, web, **tools**, context, constraints, price, pricing (кэш 10 мин) |
| `POST /api/chat` | прокси на `/chat/completions`, поток SSE (или `stream:false`) |
| `POST /api/image/generate\|edit\|multi-edit\|upscale` | прокси на картинки Venice, ответ JSON или файл как есть |
| `POST /api/fetch` `{url}` | скачать страницу/файл/архив по ссылке (до 80 МБ; localhost и частные сети запрещены) |
| `GET/PUT/DELETE /api/chats[/id]` | чаты — JSON-файлы |
| `GET/PUT/DELETE /api/projects[/id]` | проекты — JSON-файлы |
| `GET/POST/DELETE /api/usage` | статистика расходов + последний баланс |
| `GET/POST /api/key` | **только Swift**: показать/сменить ключ (проверка через `/api_keys/rate_limits`) |
| `GET /api/update[?force=1]`, `POST /api/update` | **только Swift**: есть ли новый релиз на GitHub / скачать и установить |
| `POST /api/fs/pick` | выбрать папку проекта (в приложении — окно выбора; в браузерной версии — `{path}`) и запомнить её в `folders.json` |
| `POST /api/fs/work\|put\|files\|get\|drop` | рабочие копии архивов (3.11): `work {chat, name}` создаёт `<данные>/work/<чат>/<метка>/<имя латиницей>/` и возвращает `{base, root}` (обе папки — в `folders.json`); `put {root, files:[{path, data: base64, x, append}]}` пишет файлы (большие — частями с `append`); `files {root}` — все файлы с `version`, размером и `x` (без `node_modules`, `.git`, `__pycache__`, `.venv`, `venv`, без ссылок); `get {root, path}` — сырые байты файла (и в обычной папке, там до 16 МБ: для сверки «�» в целом файле); `drop {root}` — стереть копию и убрать её из разрешённых. `put`, `files` и `drop` работают только внутри `work/` (иначе «Это можно только в рабочей копии архива»). `DELETE /api/chats/<id>` стирает и `work/<id>` |
| `POST /api/fs/info\|list\|grep\|read\|write\|edit\|undo\|run\|job\|memory\|symbols` | работа с папкой `{root, …}`: только папки из `folders.json`, выйти за пределы папки нельзя. `read`/`write`/`edit` возвращают `version` (время изменения в мкс + размер); `edit`/`write` с `expect` отказывают, если файл изменился, `write` с `mustBeNew` — если файл уже есть; `edit` возвращает `snippet` (место правки с номерами строк). `edit` с `dry:true` — проверка без записи; `write`/`edit` возвращают `backup` для `undo`; `run` — `zsh -lc` в папке, таймаут, «Стоп» убивает процесс. `run` с `background:true` — фоновая команда, сразу возвращает `job`; `job {job, wait, stop}` — новый вывод, идёт ли, код выхода (фоновые команды останавливаются в конце ответа модели и при выходе). Кнопка «Откатить все изменения» под ответом — `undo` всех правок ответа с последней к первой. В server.py — только с localhost и `Content-Type: application/json` |

### Данные пользователя (вне приложения — переживают обновления)
`~/Library/Application Support/VeniceChat/`
- `chats/*.json` — чаты (вместе с вложениями, архивами и картинками)
- `projects/*.json` — проекты (инструкции, файлы, архивы)
- `usage.json` — `{events: [...], balance: {usd, at}}`
- `folders.json` — папки, которые пользователь выбрал для проектов (только к ним есть доступ)
- `backups/<id>/` — копии файлов до правок модели (для кнопки «Отменить»)
- `memory/*.md` — заметки модели о проектах (инструмент `remember`)
- `work/<чат>/<метка>/` — рабочие копии присланных архивов (3.11): `source.zip` (исходный архив),
  `snapshot.json` (версии файлов сразу после распаковки) и `<имя>/` — файлы, которые правит ИИ;
  удаляются вместе с чатом
- `config.json` — `key` (свой ключ из настроек) и `builtinKey` (копия вшитого ключа, чтобы он пережил
  обновление из GitHub, где ключа нет); права 0600

Настройки интерфейса (тема, модель, режим, системный промпт, температура…) — в `localStorage`
веб-вида; он привязан к **bundle id `local.venice.chat`**.

> ⚠️ **Не переименовывать**: bundle id `local.venice.chat`, исполняемый файл `VeniceChat`,
> папку данных `VeniceChat`, автосохранение окна `VeniceChatMain`. Иначе у пользователя и друзей
> «пропадут» чаты/настройки. Отображаемое имя можно менять свободно (`appName` в main.swift,
> `NAME` в build.sh, `<title>` и `.brand-name` в index.html).

## 2. Сборка, установка, проверка

```bash
./venice-chat/macapp/build.sh
```
Собирает универсальное приложение (arm64 + x86_64, macOS 12+), подписывает ad-hoc, кладёт
`~/Applications/И ВСЕ 3,14здец.app` (старое «Venice Chat.app» удаляет), делает
`~/Desktop/И ВСЕ 3,14здец.dmg` (приложение + ярлык «Программы» + «Как установить.txt").
**Ключ берётся из `venice-chat/.env` и вшивается в `Resources/key.txt`.**
Перед сборкой закрыть приложение: `osascript -e 'quit app "И ВСЕ 3,14здец"'`.

**Самотест без участия человека** (печатает JSON со всеми проверками и выходит):
```bash
cd "$HOME/Applications/И ВСЕ 3,14здец.app/Contents/MacOS" && VENICE_SELFTEST=1 ./VeniceChat
```
Проверяет: библиотеки, ключ и отказ неверного ключа, модели (текст/картинки/редактор), чаты,
проекты, статистику, `/api/fetch` (и запрет localhost), мост браузера (открывает example.com),
потоковый ответ и «Стоп».

**Проверка агента на реальной задаче:**
```bash
VENICE_SELFTEST=1 VENICE_AGENTTEST="Открой … и скажи …" ./VeniceChat
# + VENICE_AGENTTEST_DENY=1 — тест сам нажимает «Запретить» на запросы разрешения
# + VENICE_AGENTTEST_ZIP=путь.zip — к заданию прикладывается архив; в ответе pack — что попало бы в готовый архив
VENICE_SELFTEST=1 VENICE_EVAL=compare ./VeniceChat   # оценка качества ответов (12 вопросов, ~$0.3–1)
```
Печатает шаги, ответ и расход; тестовый чат удаляет сам.

**Браузерная версия** — через `.claude/launch.json` (preview «venice-chat») или `python3 venice-chat/server.py`.
Экран приложения с машины разработки не виден (нет прав на запись экрана) — внешний вид
проверять в браузерной версии, поведение приложения — самотестами.

После каждой доработки: пересобрать, прогнать самотест, удалить свои тестовые чаты/проекты,
сказать пользователю, что `.dmg` обновлён.

## 3. Возможности (что уже сделано)

**Чат.** Потоковые ответы; Markdown (marked), подсветка кода (highlight.js) с кнопкой «Копировать»,
формулы (KaTeX), таблицы; блок «Размышления» (`reasoning_content` и `<think>`); копировать,
«ответить заново», редактировать своё сообщение; «Стоп» и Esc; автоназвание чата (запрос с
`disable_thinking`); поиск в интернете — с 3.5 инструмент модели `web_search` (отдельный запрос
`stream:false` с `enable_web_search:"on"` и `enable_web_citations`, ответ + источники), кнопки «Поиск»
нет; запросы агента идут с `enable_web_search:"off"`, модели без инструментов — `"auto"`.
С 3.5 все сообщения чата идут через `runAgent`, если модель умеет инструменты; выбор модели (73 текстовые).
Стоимость под каждым ответом. Библиотеки — с cdnjs (нужен интернет).

**Боковая панель.** Чаты по датам, поиск, переименование, удаление; раздел «Проекты».

**Файлы.** 📎, перетаскивание, Cmd+V. Текст/код, PDF (pdf.js), DOCX (mammoth), картинки,
ZIP (JSZip). Картинки подгоняются под требования Venice: 64×64 … 2048 (`fitImage`).
Кодировки windows-1251 / koi8-r распознаются (`decodeText`).

**Архивы (ZIP, репозитории GitHub, архивы по ссылке)** — `readZip`:
- распаковывается всё полезное; в память до 15 млн символов текста (файл — до 1,5 млн), до 60 картинок;
- всегда пропускаются зависимости (`node_modules`, `.git`, `vendor`, `.venv`…), служебные файлы
  (`*.min.js`, `.map`, lock, шрифты, видео); папки сборки (`dist`, `build`, `out`…) — **только если
  рядом есть исходники** (у готового сайта код как раз в build/dist);
- в сообщение: дерево всех файлов + главные файлы до 400 тыс. символов (≈100 тыс. токенов);
- остальное модель берёт сама инструментами: `archive_list`, `archive_read` (`offset`, `line`),
  `archive_search` (текст/regex), `archive_view_image`;
- картинки из архива **не показываются отдельными вложениями** — только карточка архива.

**Правка архива (3.11)** — `static/archive-work.js` (чистые функции, `AW`) + блок «Правка архива» в app.js:
- архив с кодом (`AW.CODE_FILE`; без кода — только если просят что-то исправить) при ответе модели с
  инструментами распаковывается в рабочую копию (`prepareWorkCopy` → `/api/fs/work|put|files`), и модель
  работает с ней как с папкой: `chat.folder = {path, name, work: true}`, данные копии — в `archive.work`
  вложения (`root`, `base`, `prefix`, `deps`, `codeDir`, `media`, `touched`). Правки — без вопросов (всё
  откатывается), команды — с разрешением; `remember` и git-блок убраны, вместо правил 9–10 и в конце —
  правила архива (`workRules`); вместо старого текста архива в истории — заметка (`toApi(m, workContext(chat))`:
  своя копия, прежняя версия того же архива — `supersededArchives`: только читаемый архив с тем же именем,
  присланный раньше активного (не в том же сообщении; тот же файл, приложенный дважды, — `sameArchive` — тоже
  прежняя версия: совпадает отпечаток `archive.sig` — имена, размеры и CRC32 всех файлов из оглавления zip,
  `zipSig` (у пустого файла JSZip хранит не оглавление, а обещание — считается с CRC32 0); у архивов без
  отпечатка — имена и размеры файлов, сохранённые тексты и картинки), — или другой архив); прежние версии не предлагаются и в `archive_*` (`archivesForTool`). Почти весь код в dist/ или build/ без исходников рядом
  (снаружи — не больше двух файлов, и только в корне) — `codeDir`: карта кода корня и этой папки вместе;
- одна общая папка архива (Finder «site/», GitHub «repo-main/») в копии убрана и возвращается при сборке;
  не распаковываются зависимости и .git (`UNPACK_SKIP`), ссылки, файлы больше 50 МБ, пути длиннее 800 байт
  (на Mac весь путь — до 1024) и пути с пробелом по краям (сервер их срезает) — в готовом архиве они
  остаются байт в байт; опасные пути (../, /abs, C:\, NUL,
  имена длиннее 255 байт) и мусор (__MACOSX, .DS_Store, Thumbs.db, ._*) из готового архива убираются.
  Имена без флага UTF-8 читаются как cp866 (Проводник Windows); пути через «\» (PowerShell) в готовом
  архиве становятся обычными «/» («X\» — папкой); время изменённых файлов — время правки в копии
  (из версии «<мкс>-<размер>»), по местным часам, в пределах 1980–2107 (больше zip не вмещает);
- «Скачать готовый архив» (карточка под последним ответом и чип в поле ввода) — `packWork`: исходный zip,
  где изменённые файлы заменены (если байты не совпали с оригиналом), новые добавлены (кроме служебных:
  node_modules, __pycache__, Pods, .gradle, новые dist/build, .log, .zip), удалённые убраны; остальное —
  байт в байт. Карточка появляется, только если копию правили (edit/write или команда, которая правда
  выполнялась: отказы приложения — `notRun`);
  Имя «X (готово).zip»; в приложении — окно «Сохранить как» через мост `saveImage`;
- «Ответить заново» и правка вопроса откатывают правки копии из убранных ответов (`revertDropped`) — вместе
  с тем, что команды того же ответа сделали с этими файлами. Если после первой убранной правки файла
  пользователь кнопкой отменил более раннюю (время правки `step.at` и отмены `step.undoneAt`), правки до
  этой отмены не откатываются (иначе вернулось бы отменённое), после неё — откатываются; у шагов из старых
  версий без `step.at` время берётся из их порядка в чате. Файл, где не откатилось ничего, называет
  всплывашка. Отмена из сборок без `step.undoneAt` (время неизвестно): если первая убранная правка файла
  тоже оттуда, файл оставляем как есть. Изменения команд (`step.cmd`, и упавших тоже) в других файлах и
  сделанные до первой правки файла остаются — всплывашка говорит «могло остаться» (если были только
  команды — «То, что сделали команды прошлого ответа, не отменяется»). Не вышло ничего — «Не удалось
  отменить правки…» с теми же оговорками (без них — «файл остался изменённым»; неудачи считаются по
  файлам — `failedIn`), копии нет на диске — так и говорит; убрано несколько ответов — «Правки убранных
  ответов…»; чат удалили во время отката — откат останавливается, всплывашек нет. Пока идёт откат
  (`reverting`), новое сообщение, «Ответить заново», правка вопроса, «×2» под картинкой, «Скачать готовый
  архив», «Отменить» и «Откатить все» не выполняются — «Подождите: отменяю правки»; так же — пока идут
  «Отменить» и «Откатить все» (они тоже ставят `reverting`). `undo` заново создаёт папку файла (её могла
  переместить или стереть команда), ссылку внутри копии на месте файла заменяет, а не пишет туда, куда она
  ведёт (ссылку, ведущую за пределы копии, не трогает — отмена говорит, что путь ведёт за пределы папки),
  и отвечает по-русски;
- копии убранных сообщений стираются (`dropOrphanCopies`), копии удалённого чата — тоже (`drop_work` /
  `dropChatWork`). Удаление копии (`forget_tree` / `forgetTree`): сначала закрывается доступ к ней (запись,
  пришедшая позже, получит «Рабочей копии архива больше нет» — `GONE_WORK`), затем останавливаются команды,
  запущенные в ней, и всё, что ещё работает в её папке, — по рабочей папке процесса (`pids_in` / `pidsIn`:
  /proc или lsof, lsof ждём не дольше 15 с), так находится и то, что пережило свою оболочку (cmd &, вывод
  в файл, setsid): SIGTERM, через 3 с — SIGKILL; и только потом папка стирается. Запись в копию
  (put/write/edit/undo) идёт под `work_lock` / `workLock` и перепроверяет доступ, закрытие доступа — под тем
  же замком: запись, начатая раньше, к стиранию уже закончилась, новая получает отказ — стёртое не
  пересоздаётся, а само стирание идёт без замка (большая копия не держит другие чаты); для удалённого чата
  новых копий не бывает (`dropped_chats` / `droppedChats`). В app.js удаление чата сначала ставит `chat.deleted`, останавливает ответ и ждёт начатых
  сохранений (`S.saving`); ответ, откат и сводка удалённого чата ничего не пишут. В Swift `stopTree` и сам
  добивает через 3 с (таймаут, «Стоп», остановка фоновой команды), как `stop_tree` в Python;
- только чтение (с причиной в шагах и в правилах модели): у чата есть своя папка или папка проекта
  (`roFolder` — отключили папку, и архив снова правится; архивы из файлов проекта при подключённой папке
  тоже только читаются — `readOnlyWhy`: архив не из сообщений чата — из проекта; модели: «правки в папке, с
  которой ты работаешь, его не меняют»), другой архив уже правится (правится один — из последнего
  сообщения, что открылся и прошёл лимиты, с большим числом файлов кода; `roOther` — корень той копии: в
  работе уже не она — архив, который не новее копии в работе, остаётся только для чтения с её именем, более
  новый (и любой, когда копии нет) — снова в очереди; одноимённые — «другой архив с тем же именем»; тот же
  архив, присланный ещё раз или приложенный дважды, — без пометки в шагах; одинаковая заметка в ответе — один раз),
  больше 100 МБ / 10 000 файлов / 300 МБ,
  архив прислан до перезапуска приложения (байты держатся в памяти — `ZIP_SRC`; тот же архив, присланный
  заново, заменяет старый в правилах модели и про старый не пишется — `roResent`, пока у нового есть байты
  или копия: новый убрали — снова пишем), подпапка GitHub `/tree/` (`noEdit`), сбой распаковки (`roFail` — разовый флаг: при следующем
  запросе пробуем ещё раз; `roRetry` — счётчик, чтобы попытка была одна), модель без инструментов (тогда
  архив идёт текстом). Архив без кода и без текстов (одни картинки) не распаковывается. Текстовый архив
  без кода, пока правится другая копия, только читается (`roTemp` — причина пересчитывается при каждом
  запросе и называет копию, что в работе после распаковки). Копия пропала с диска посреди работы — в этом
  ответе все архивы только читаются (причины, называвшие пропавшую копию, заменяются, с `roTemp` — в следующем
  запросе их пересчитают); заметка: «…пропала с диска вместе с правками — … Если ИИ снова будет его править,
  то начнёт с исходных файлов» (архив прислан до перезапуска — «прикрепите архив заново»);
- «�» в вызовах инструментов и в ответе: сбоем считаются только новые слова с «�» (слова сравниваются
  целиком и с подсчётом). Настоящие — слова, которые уже есть у пользователя: в его сообщениях, вложениях,
  описании, инструкциях и файлах проекта (`userBroken`), — и в файлах, выводах команд и заметках о папке,
  которые ИИ видел в этом чате (`msg.seenBroken`, сохраняется с сообщением, 500 последних; слова из имени папки, списка «В корне» и
  «Файлов по папкам», карты кода и заметок о папке берут заново в каждом ответе с папкой — `FOLDER_BROKEN`, в памяти, — а последние 500
  из них хранит чат, `chat.folderBroken` (заменяются каждым таким ответом): их знают и ответы без папки;
  всё вместе — `knownBroken`). У пользователя считаются и имена его вложений, название проекта и имена его файлов.
  Их можно искать, править и цитировать, `repairBroken` их не трогает. В `seenBroken` не попадают слова,
  которые модель сама написала в вызове (их повторяют ошибки и отказ `BROKEN_TEXT`), и отчёт разведчика
  (его пишет модель). Для действий, которые что-то меняют (правка, запись, команда), слово из одних «�»
  считается настоящим, только если оно есть у пользователя или встречается не чаще, чем в заменяемом
  тексте: «�»/«��» есть почти в любом файле в чужой кодировке. Команды, которые только читают (`isSafeCommand`,
  grep/rg без перенаправлений), проверяются как поиск. Отказы считаются по каждому вызову (`brokenTry`, в
  памяти): тот же вызов после `BROKEN_RETRIES` отказов выполняется, а остальные проверяются дальше. Слова ищутся в строках аргументов как есть
  (`argStrings`), «\n», «\b» к слову не прилипают. write_file сверяет слова с «�» с прежним файлом
  (прочитан не весь — с целым файлом через `/api/fs/get`, в любой папке; не вышло — ищет слова в файле через
  grep сервера, `missingIn`: буква после «\n» — начало слова, слово из одних «�» — не реже, чем в новом тексте,
  по строкам, больше 12 слов — новые; lookbehind там можно, в JS-регулярках нельзя: Safari 15 на macOS 12),
  edit_file — с заменяемым текстом. `repairBroken` чинит ответ и заметки модели в шагах (`say`): каждое
  испорченное место — целый кусок между пробелами со своим местом (одинаковые «��» бывают разными буквами),
  замена по месту. Известное ограничение: если к настоящему слову с «�» прилипла испорченная кавычка, кусок
  чинится целиком.
  Текст в cp1251: байт 0x98 (в cp1251 его нет) становится «�», как у сервера.

**Ссылки в сообщении** (до 3, можно выключить в настройках): репозиторий GitHub (архив
`/archive/HEAD.zip`), папка `/tree/...` (быстро через git trees API + raw), файл `/blob/...` (raw),
веб-страница (текст из HTML), PDF, ZIP. Только публичные репозитории.

**Картинки.** Режимы «Картинка» (43 модели) и «Редактор» (28 моделей) рядом с «Чат»; цена у
каждой модели; пропорции и разрешение из `constraints` модели; кнопки на картинке «Изменить»,
«×2» (upscaler), «Скачать» (в приложении — системное «Сохранить как»), просмотр на весь экран.
Редактор без вложения правит последнюю картинку чата. Безопасный режим (`safe_mode`, по
умолчанию вкл.) и «убрать водяной знак» (`hide_watermark`) — в настройках.

**Проекты.** Название, описание, инструкции, файлы (включая архивы и ссылки), список чатов;
инструкции и файлы идут в системный промпт каждого чата проекта; перенос чата в проект (меню
в шапке); удаление проекта оставляет чаты. Лимит файлов ≈750 тыс. токенов, показывается цена
«к каждому сообщению» и предупреждение, если больше контекста модели.

**Встроенный браузер (только приложение для Mac).** Панель справа (адресная строка, назад/вперёд,
обновить; Cmd+B). Отдельной кнопки нет: браузер — инструмент модели, он всегда доступен в режиме чата
(выключается в Настройках: «Модель может открывать сайты…», `settings.browserTool`). Панель появляется сама,
когда модель открывает страницу или нажимает на ней. Поэтому в приложении все сообщения чата идут через `runAgent`.
Инструменты: `browser_open`, `browser_read` (текст + пронумерованные элементы `[N]`),
`browser_click`, `browser_type`, `browser_scroll`, `browser_back`, `browser_screenshot`.
Скрипты в странице выполняются в отдельном content world. Входы на сайты сохраняются.
**Защита:** клики по отправке форм/«купить/оплатить/удалить/отправить…» и отправка форм (кроме
поиска) — только после «Разрешить»; пароли модель не вводит; текст страниц — данные, не команды.
До 30 шагов (с архивами — 60); старые результаты сокращаются в истории.

**Папка проекта (версия 3.3; с 3.5 — часть проекта).** С 3.5 папка принадлежит проекту: `project.folder =
{path, name}` (карточка «Папка на компьютере» на странице проекта; в боковой панели одна кнопка «+»; с 3.10.1 отдельной кнопки
«Новый проект из папки» нет — она путала, остался только вариант в пустом списке проектов; та же папка второй раз
открывает существующий проект). Все чаты проекта работают с ней
(`folderOf(chat)` = `chat.folder` или папка проекта). Кнопки «Папка» в поле ввода нет; у старых чатов
может остаться своя `chat.folder` (чип с ×), `S.pendingFolder` остался для самотеста. Модель работает как Claude Code:
не получает весь код сразу, а сама ищет и читает нужное. Инструменты (`FS_TOOLS` в app.js):
`list_files` (шаблоны `**/*.ts`), `grep` (текст/regex, glob, context), `read_file` (с номерами строк,
offset/limit), `edit_file` (точная замена куска old→new, должен быть уникален), `write_file`,
`run_command` (тесты, сборка, git), `remember` (заметки о проекте), `update_plan` (план над ответом).
С версии 3.4 ещё: `code_map` (карта кода: функции/классы/типы с номерами строк, `/api/fs/symbols`,
шаблоны в `Workspace.symbolPatterns` / `SYMBOL_PATTERNS`), `find_symbol` (объявления + упоминания через
grep), `explore` (помощник-разведчик: отдельный разговор только с инструментами чтения, до 40 шагов,
возвращает отчёт; модель — Настройки → «Модель для помощников-разведчиков»), `propose_plan` (план
крупной задачи с кнопками «Выполнить план» / «Нет, обсудим»). Чтения, поиски и explore из одного ответа
модели выполняются параллельно (`PARALLEL_TOOLS`). Карта кода (до 16 тыс. символов) идёт в системный промпт.
Правки и команды — только после «Разрешить» (или «Разрешать правки/команды в этом чате» —
`chat.folderTrust`); у правки видна разница, после — «Показать изменения» и «Отменить».
В начале задачи в системный промпт идут: корень папки, число файлов по папкам, `AGENTS.md` /
`CLAUDE.md` / `.cursorrules` / начало `README.md` проекта и заметки `remember`.
До 250 шагов и лимит денег на задачу (Настройки → «Лимит на одну задачу с папкой или архивом», по умолчанию $1).
Когда старых результатов работы с папкой (кроме последних 4, explore и плана) набирается больше 40 тыс.
символов, они разом укорачиваются до начала с пометкой (`maskOldResults`) — пачкой, чтобы кэш Venice
не сбрасывался на каждом шаге. Когда запрос превышает 60% контекста модели (не больше 120 тыс. токенов),
модель пишет сводку и работа продолжается с неё (`compactConvo`).
С 3.5: правка или перезапись файла принимается, только если модель читала его и он с тех пор не менялся
(`READS` — путь → `version`, обновляется после её же правок; помощники-разведчики не считаются);
после `edit_file` модель получает место правки. Команды, которые только смотрят (`isSafeCommand`:
git status/diff/log/show/branch, ls, cat, head, tail, wc…, без `; & | > <` и подстановок), идут без
подтверждения. Правила в `folderRules`: git (ветка под крупную задачу при чистой рабочей копии, коммит
только своих файлов с описанием, без push/reset/force) и «проверка глазами» (dev-сервер в фоне →
browser_open http://localhost:… → browser_screenshot → остановить). Под ответом — карточка «Изменено N
файлов» (+/− строк, разница по клику) с кнопкой «Откатить все изменения» (`changesHtml`). Команды и
по таймауту, и по «Стоп» останавливаются вместе с дочерними процессами.
С 3.5.1 ответы идут в нескольких чатах сразу: `S.streams` (id чата → поток), `S.stream` — геттер потока
открытого чата, `streamOf(chat)`. Вопрос «Разрешить» ждёт сколько угодно, пока пользователь в другом чате
(в списке чатов значок, всплывает подсказка); «Стоп» и конец ответа снимают только вопросы своего ответа.
С 3.6 (после задачи, где слабая модель сделала ~830 шагов вместо «убрать скрипты из HTML»): в начале
`folderRules` блок «Главное» — делать только то, что просили, изучать 5–15 шагов, большой файл
обрабатывать одним скриптом; «проверка глазами» — один снимок, без попиксельных сравнений.
Если ответ упёрся в лимит шагов или денег, модель пишет сводку (`workSummary`) в `msg.workNote`, и она
уходит в историю вместо списка действий (тот теперь не длиннее 30) — «продолжай» начинает с того же места.
Третий одинаковый вызов получает пометку «ты делаешь это уже N-й раз»; каждые 40 шагов (`CHECKPOINT`)
модель сверяет работу с задачей. run_command с `&`/`nohup` отклоняется (`LEFT_RUNNING`) — для фона есть
background. Безопасные команды из одного ответа идут параллельно.
С 3.6.1 (реальная проверка 3.6: 343 шага, playwright install, удаление папки сайта, 50+ чтений одного
файла кусками): установка программ/браузеров/пакетов (`INSTALL_RE`) отклоняется, если пользователь сам не
писал про установку (`ASKED_INSTALL`); `rm -r`, `find -delete`, `git clean/reset --hard/checkout .`
(`DANGER_RE`) всегда спрашивают, даже при «разрешать в этом чате», и без этой кнопки; чтение одного файла
кусками (`fileTargets`) — каждый 8-й раз подсказка «напиши один скрипт»; фоновая команда дольше 3 минут —
подсказка остановить её; при остановке по лимиту сводка «Где остановился» видна в ответе.
Проверка на реальной задаче: `VENICE_SELFTEST=1 VENICE_AGENTTEST="…" VENICE_AGENTTEST_FOLDER=/путь ./VeniceChat`.

**Оформление.** Тема: как в системе / светлая / тёмная (заголовок окна тоже). Иконка и логотип π.

**Использование** (Настройки → вкладка). Плитки (потрачено, запросы, токены, картинки, баланс),
столбцы по дням с разбивкой по моделям (палитра из навыка dataviz, 5 цветов + «Другие»),
таблица по моделям, периоды 7/30/всё время. Текст — точная цена из потока (`cost.usd`),
картинки — по ценам моделей (≈). Баланс — из заголовка `x-venice-balance-usd`.

**Аккаунт Venice** (Настройки → «Основные»). Текущий ключ (маска), смена с проверкой,
«Вернуть встроенный», кнопки «Открыть venice.ai» и «Где создать свой API-ключ».

**Раздача друзьям.** `.dmg` с **ключом владельца** (так решил пользователь, риски объяснены: все
тратят его баланс, ключ можно извлечь; совет — отдельный ключ для друзей). Приложение не
нотаризовано → при первом запуске «Всё равно открыть» в настройках безопасности (в инструкции).

## 4. Особенности Venice API (выяснено на практике)

- Базовый адрес `https://api.venice.ai/api/v1`, совместим с OpenAI. Спецификация:
  `https://api.venice.ai/api/v1/swagger.yaml`.
- `GET /models?type=text|image|inpaint|upscale` — без ключа тоже работает; `model_spec.capabilities`
  (`supportsVision`, `supportsFunctionCalling`, `supportsReasoning`, `supportsWebSearch`),
  `constraints` (aspectRatios, resolutions, widthHeightDivisor…), `pricing`.
- Модель по умолчанию `deepseek-v4-1-flash-1017-uncensored`: зрение, инструменты, 1 млн контекста,
  $0.33 / $1.32 за 1 млн токенов (кэш входа $0.00825).
- Поток: `stream_options: {include_usage: true}` → в конце `usage` и **`cost.usd`**. Инструменты
  в потоке — стандартные `delta.tool_calls[{index,id,function:{name,arguments}}]`, `finish_reason: tool_calls`.
- `venice_parameters`: `include_venice_system_prompt` (по умолчанию добавляет ~1,5 тыс. токенов),
  `enable_web_search: on|off`, `disable_thinking`, `strip_thinking_response`.
- Картинки во входе — не меньше 64×64.
- `/image/generate`: `width/height` ≤ 1280 (для моделей без aspectRatios), иначе `aspect_ratio`;
  `resolution` для моделей с тарифами 1K/2K/4K; `format: webp`, `return_binary: false`,
  `hide_watermark`, `safe_mode` (по умолчанию true — размытие 18+). Ответ — base64 в `images`.
- `/image/edit` — `image` как data URL, ответ — сам файл; несколько картинок — `/image/multi-edit`.
- `/image/upscale` — `image` **без префикса `data:`** (иначе «incomplete or corrupted»), `scale` 2 или 4.
- Баланс — заголовок `x-venice-balance-usd` в каждом ответе.
- `/billing/*` (статистика, баланс) — **только с админ-ключом**; обычный ключ — 401. Админ-ключ в
  раздаваемое приложение не вшивать.
- Проверка ключа без затрат — `GET /api_keys/rate_limits` (200 / 401).
- Изредка (5 чатов из 225) deepseek-v4-1-flash присылает вместо части русской буквы символ `�` (U+FFFD,
  по одному на каждый байт разрезанного символа) — исходные байты теряются уже у Venice. Поэтому
  `repairBroken` после ответа восстанавливает слова коротким запросом, а `brokenArgs` не выполняет вызов
  инструмента с `�` (просит модель повторить, до 4 раз) — иначе испорченные буквы попали бы в файлы.

## 5. Хронология запросов пользователя

1. Локальная оболочка для своего ключа Venice → Python-сервер + страница.
2. Прикрепление файлов → картинки, PDF, DOCX, текст.
3. ZIP-архивы.
4. Ошибка «картинка меньше 64×64» → автоувеличение.
5. Приложение для Mac → WKWebView-обёртка.
